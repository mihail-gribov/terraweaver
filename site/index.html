Why it is different

The memory belongs to you, not to the app you use today.

Today a memory lives inside one assistant and is tied to it. TerraWeaver is a layer of its own: yours, portable, and open to any agent.

1

Yours, for any agent

An MCP server with two doors: say (the conversation) and ask (the agent's questions). Works with the Claude Code plugin or any MCP client. Plain files per user, the journal facts.md and the graph as JSON lines, that you can copy and move. Switch agents and keep your history.

2

Remembers on its own

Nothing to tell it. It catches what matters in passing, between work questions, and settles "yes please" from the agent's question before it. Two one-token Nemotron filters keep the noise out.

3

Trust: your own words

Every fact keeps the entry it came from, with its day, so you can see what you actually said. Your private matters never reach the web, and names are kept out of web queries by code.

4

Quality: time, change, links

It knows what holds now and what used to; topics and people are linked. Topics you still care about are kept current from the web (one search per topic a month, never on dormant topics). Reading costs the same per message on day one as after a year.

Measured

43 of 45, and the two misses.

Five short personal histories (family, books, running, home, trips): a dozen talks over two months among thirty of everyday talk, each told to a fresh memory and checked by words. The first run of the day gave 39 of 45; 43 of 45 came after the fixes the misses pointed at. The histories were seen during development, so the second number is tuned on them.

The misses are real: a car-alarm question that did not bring up the user's Skoda Octavia, and a sale of a Golf that was never told, which the memory answered instead of declining. One run measures little here: the spread between runs is as large as the differences. You can run it yourself: set -a; . ./.env; set +a; .venv/bin/python benchmarks/scenarios.py --only books (needs a Nebius key, about nine minutes for one story; see the benchmark notes).

Connect

Two ways in. Only one is for your life.

The memory is an MCP server: any agent can use say and ask. With the Claude Code plugin the hooks call say by themselves.

Your own memory

Runs on your machine and listens on it only: no key needed to reach it. This is the real thing.

  1. Needs Python 3.12+, Claude Code, and your own keys for Nebius Token Factory and Tavily (for the models and the web, not for the memory).
  2. Clone, install and start the memory: 
    git clone https://github.com/mihail-gribov/terraweaver
cd terraweaver
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m memory.server
  3. In another terminal, Claude Code with the plugin: 
    adapters/claude_code/claude-personal
  4. Talk about your life in passing. What it keeps is in var/memory/main/facts.md.

The hosted demo

For evaluation, by key. Not a place for your life.

  1. You need Claude Code or another MCP client, and a key: sign in with Google (a Google account is the only requirement) and make one in your account (tw_…, shown once). No Google account? A reviewer token works the same way; it is given with the submission.
  2. Point your agent at it: 
    export PERSONAL_MEMORY_URL=https://terraweaver.life
export PERSONAL_MEMORY_TOKEN=tw_...
adapters/claude_code/claude-personal
    Any other MCP client: https://terraweaver.life/mcp, header Authorization: Bearer tw_....

One shared memory, for evaluation only. Do not enter personal data: everything typed goes into a shared journal that anyone with a key can see, and it may be erased. Use an invented person.

Under the hood

NVIDIA Nemotron on Nebius Token Factory.

Each model sits where it pays. Closed questions are answered from the first token's logprobs: one token, a probability instead of a guess.

RoleModel
Rewrite, read, decideNemotron 3 Super 120B-A12B
Judge: hundreds of small closed questionsNemotron 3 Nano 30B-A3B
Search by meaning: embeddings (on the demo, through OpenRouter)NVIDIA Nemotron embed 1B
